Файлы запускаются **по порядку номеров** в Supabase → SQL Editor → New query → вставить → Run.
Каждый можно запускать повторно — они не ломаются от второго запуска.

## Правило на будущее
Новый файл = следующий номер и понятное имя: `07_что_делает.sql`.
Никогда не редактируем уже запущенный файл — только добавляем новый.
Причина: в базе уже применено старое, и правка задним числом ничего не изменит.

## Ключи
- В сайте (`config.js`) — только **публичный** ключ (`sb_publishable_...`). Так и должно быть.
- **service_role** — полный доступ к базе, живёт ТОЛЬКО в GitHub Secrets для рассылки. Никогда в коде сайта.

## Как теперь применяются миграции
Клод прогоняет их сам: `node scripts/sql.mjs supabase/12_имя.sql`
Строка подключения — в `~/.nishemap-db` (600, вне репозитория).
Разовый запрос: `node scripts/sql.mjs -q "select ..."`

## Монеты: считает сервер (12 + 14)

С `12_ledger.sql` баланс перестал жить в браузере. Начисляют только триггеры на
`submissions`, `menu_photos`, `price_updates` — устройство и повод берутся из
уже проверенной строки, а не из аргументов клиента. Монета зреет 15 минут с
геометкой и 60 без неё.

| Дверь | Кому | Зачем |
|---|---|---|
| `coin_balance(device)` | anon | единственное, что видит приложение |
| `coin_ledger` | никому (401) | журнал целиком не читается и не пишется |
| `award_coins(...)` | никому (401) | иначе любой выпишет себе 1000 монет из консоли |
| `coin_top` | владельцу через сервисный ключ | таблица лидеров по реальным монетам |

Топ-10: `./tools/coin_top.sh` (нужен `.supabase_token`).

Скрытие в модерации гасит монеты: триггер `void_coins_on_override_trg`
(`14_ledger_hooks.sql`) переводит начисления по позиции в `void`.

**Чего это НЕ чинит.** Человек по-прежнему может нарисовать себе любое число на
своём экране — это его браузер. Важно, что сервер этого числа не видит: журнал,
таблица лидеров и всё, что когда-нибудь будет давать за монеты, читают только
`coin_ledger`. Панель разработчика заперта на ключ (SHA-256 в `js/app.js`),
но это замок от любопытных, а не защита баланса.

## 16-18: монета жалобщику, аватары и личность

**Монета за правоту.** Жалоба теперь подписана устройством (`reports.device`).
Когда владелец кнопкой ⚪ делает монету серой, `overrides.by_owner` = true и
триггер `pay_reporters_trg` начисляет по монете каждому, кто жаловался.
Автоматическое посерение по трём жалобам НЕ платит — иначе трое сговорившихся
жалуются друг другу и печатают монеты. Повторное нажатие не доплачивает:
не даёт `unique (device, kind, ref)`.

**Аватары.** Цена лежит в `avatar_prices`, покупка идёт через `buy_avatar()`,
купленное — в `purchases` (аноним не читает). Клиент только показывает.
Отдельно `check_avatar_owned_trg` стирает `submissions.avatar`, если аватар не
куплен: эту подпись видят все, кто открыл карточку, значит она не косметика.

**Личность.** `tg_users` заполняет только воркер: он один умеет проверить
подпись `initData` ключом бота (`/auth`, `checkInitData`). Поддельную подпись
он отбивает, подписи старше суток тоже. Аноним таблицу не видит.

⚠️ **Правовое.** `tg_users` хранит имя и @username живых людей — это
персональные данные, а база в eu-west-1. 152-ФЗ требует, чтобы персданные
россиян лежали на серверах в России. До сих пор проект этого избегал
сознательно (случайный `device` вместо учёток). Решение принято владельцем;
если понадобится откатить — таблица одна и удаляется целиком.

## 19: монеты с именами

`user_top` соединяет журнал с `tg_users` по `device`. Смотреть —
`./tools/coin_top.sh [сколько]`. Кто не заходил через Telegram, показан хвостом
своего device: пока человек не открыл мини-апп, имени у него просто нет.

Оговорка: `tg_users` хранит последний device человека. Если он откроет карту в
другом браузере, старые монеты останутся на прежней строке. Пока это устраивает —
подавляющее большинство заходит из Telegram, и device там один.
