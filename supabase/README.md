# База данных НищеMap — что где лежит

Файлы запускаются **по порядку номеров** в Supabase → SQL Editor → New query → вставить → Run.
Каждый можно запускать повторно — они не ломаются от второго запуска.

| Файл | Что делает | Запущен? |
|---|---|---|
| `01_core.sql` | Таблица `submissions` (сданные цены) — основа всего | ✅ да |
| `02_photos_reports.sql` | Фото меню (`item_photos`), жалобы (`reports`), доступ к хранилищу, колонки координат | ✅ да |
| `03_confirms.sql` | Народные подтверждения цен (`confirms`) — «Ещё по этой цене?» | ✅ да |
| `04_digest.sql` | Просмотры (`views`), подписчики бота (`subscribers`), служебная `kv`, колонка `device` | ✅ да |
| `05_hardening.sql` | Безопасность: лимит размера фото, лимиты частоты, запрет подтверждать свою цену | ✅ да |
| `06_avatars_limits.sql` | Аватары + починка лимитов (в 05 их можно было обойти) + счётчик просмотров места | ✅ да |
| `07_avatar_shop.sql` | (устарел — перекрыт файлом 08, можно пропустить) | ⏭ пропустить |
| `08_avatars_v2.sql` | (устарел — перекрыт файлом 09, можно пропустить) | ⏭ пропустить |
| `09_avatars_v3.sql` | Финальный набор: 6 бесплатных (3м/3ж) + 11 за монеты | ⬜ **запустить** |

**Старые имена** (если встретишь в переписке): `schema.sql`=01, `addon.sql`=02, `addon2.sql`=03,
`addon3.sql`=04, `addon4.sql`=05. Переименованы, чтобы порядок был очевиден.

## Правило на будущее
Новый файл = следующий номер и понятное имя: `07_что_делает.sql`.
Никогда не редактируем уже запущенный файл — только добавляем новый.
Причина: в базе уже применено старое, и правка задним числом ничего не изменит.

## Ключи
- В сайте (`config.js`) — только **публичный** ключ (`sb_publishable_...`). Так и должно быть.
- **service_role** — полный доступ к базе, живёт ТОЛЬКО в GitHub Secrets для рассылки. Никогда в коде сайта.
